  | abstain 선택 (idx=60) | 0/60 | 1/14 | **4/38** |
  | abstain_p 중앙 | 0.00 | 0.11 | **0.11** |
  | abstain_p > 0.3 | 0/60 | 0/14 | **7/38 (18%)** ⚠️ |
  | abstain_p 최대 | 0.16 | ~0.22 | **0.81** |
  | pool | 60 | 60 | 60 |
- **실제 발동 사례 (7건, τ=0.3 초과)**: ap 0.81("아까" 16:39), 0.49("일단" 16:52), 0.42("cron에" 18:31), 0.34("지금" 16:14) 등 — **soft gate가 이미 빈 컨텍스트를 반환하고 있음**
- 분포: q25 0.06 / 중앙 0.11 / q75 0.27 / max 0.81 — **10-06(전부 <0.17) 대비 확연한 상향 이동**

### 현재 상태
- **▶ v7 (2026-10-07 후반)**: **3-AI v6 답변 3/3 "τ 유지 + 실측 선행"** 수신 (a-ai: 0콜 감사 / b-ai: 14건 라벨링·τ 상향 금지 / c-ai: 200콜 1회 τ 스윕). **τ 감사 완료 (stage95, 0콜)**: stage85 정답군(valid/yes) 132건 production-exact **abstain_p>0.3 = 0건** (max 0.160) — **τ=0.3 유지 근거 확보**, 정답 오차단 0. 단 stage87 raw는 abstain_p 미저장 (a-ai 감사 지점 — stage84/85로 대체 검증). c-ai 지적: **stage84 k60 op abstain 3건 (gold rank 8)** = 정답이 pool에 있는데 abstain하는 케이스 — τ와 무관한 모델 판정 문제. b-ai: abstain_p 상향은 **비교 모집단 차이** (10-06 live60 재생 vs 10-07 trace 전량) — "추세" 단정 금지, 7+7건 라벨링으로 정직 거부 여부 판정 필요.
- **"soft gate dead code"는 10-07 후반부 기준 폐기** — 부분 발동(18%) 시작
- abstain_p 상향 추세가 예상보다 가파름 → **τ 재조정·canary 가치가 시급해짐**
- 보류 유지 (단, 우선순위 상향)

### 판단 요청
1. **이미 7/38(18%)에서 gate가 발동 중** — τ=0.3 유지 시 실발동(빈 컨텍스트)이 계속 늘어나는 상황. **이걸 의도한 동작으로 받아들일지, τ 상향(0.4~0.5)으로 늦출지**
2. abstain_p 0.81 같은 고확률 abstain이 "정직한 거부"인지 "과다거부"인지 (op 정답 쿼리에서도 발동하는지 확인 필요)
3. canary(사안 D)를 **즉시 활성화**해서 추세를 모니터링할지
