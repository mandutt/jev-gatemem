- **A**: "즉시 실행(Go)" — 3차 보고서를 그대로 신뢰하고 runbook만 제안 (재인용 패턴, 검증 가치 낮음)
- **B**: **조건부 진행** — 1~3단계(skip_shadow, 사후 파일럿, probe)는 즉시, **4단계는 선행 조건 3개** (독립 홀드아웃+무답 세트를 4단계 앞으로, 표본/가드레일 수치 정합, primary 비교+사전 등록). **3차 보고서의 사실 오류 4건을 정확히 지적** — 4건 모두 실측으로 확정
- **C**: **문구·프로토콜 수정 4곳 후 Go** (primary contrast 사전 지정, Recall@3 정의 분리, probe 성공 기준 보강, 137행 proxy 명칭) — 4건 모두 타당, 1건은 실측으로 재확인

**이번 라운드의 가장 중요한 실측**: 3차 보고서가 "순서 불변성 27/27 통과"라고 단언한 실측은 실제로 **후보 순서를 섞지 않은 3회 단순 반복 = 재현성 검증**이었고 (B① 지적 정확), "경계 구간 몰림 37.3%"은 **집계 오류**였으며 (실측 34.3%, 그것도 "몰림" 아님), archived 137행은 **재판정 SKIP 24행 + superseded 113행**의 혼합이었습니다 (B② 지적 정확). **내 직전 보고서가 요청서에 "실측 확정"으로 실어 보낼 뻔한 수치 3건을 B가 잡아냈습니다.**

## 2. 실측 검증 — B의 사실 지적 4건 (전부 확정)

### 2.1 "순서 불변성 27/27" → 명칭 오류: **재현성(test-retest)** ✅ B 정확

`runC_repeat27.py` 원문 (L53-60):
```python
for rep in range(3):
    scores = jev.judge_many({'query': q}, contents, INSTR)   # contents = pools[qi] — 순서 변경 없음
    order = sorted(range(len(contents)), key=lambda i: -scores[i])
```
- **후보 순서를 섞지 않고 동일 순서로 3회 반복** — "순서 불변성"이 아니라 "재현성"입니다. B 지적 확정.
- 27/27 완전 결정적 = **같은 입력·같은 순서에서 점수 노이즈 없음** (짝지은 비교의 잡음 요인 제거 — 유용한 실측이긴 함).
- **B의 "API 응답 캐시 가능성"도 미해소**: 같은 payload 3연속 호출이면 서버 캐시 여지 존재. → 순서 셔플 검증은 probe ③에 포함 (B안대로). 순서 불변성은 **아직 미검증** 상태로 정정.
- 3차 보고서 §9 수정 #6 ("순서 불변성 27/27을 §1A에 추가") → **"재현성 27/27"으로 정정 후 반영** (B 경고: 그대로 두면 브리프 오류 전파 재발).

### 2.2 archived 137행 = **재판정 SKIP 24행 + superseded 113행** ✅ B 정확

라이브 mnemosyne.db 실측:
| 구성 | 행 수 | 원문 보유 |
|---|---|---|
| `valid_until IS NOT NULL` (총) | **137** | 137/137 |
| └ `superseded_by IS NOT NULL` (대체 archived) | **113** | 113/113 |
| └ `valid_until`만 (vu_only) | **24** | 24/24 |
| 24행 metadata_json `gate` 값 | **전부 `fail_open:http-403`** | — |

- 3차 보고서의 "archived 137행 = 재판정 SKIP 대리 표본"은 **구성 오류** — 실제 재판정 SKIP은 **24행** (전수 `gate=fail_open:http-403`, 10-01 장애분과 일치).
- **137행 전부를 SKIP proxy로 쓰면 안 됨**: 113행은 "다른 기억으로 대체(supersede)"로 archived된 행으로 SKIP 메커니즘과 다름.
- C의 명칭 제안 **"rejudge-SKIP proxy audit"** 채택 (표 제목 고정). superseded 113행은 "대체 후에도 후회되는가"라는 별개 질문의 보조 표본으로만 사용 가능.
- 파일럿 전 메타데이터 분해(`gate`, `incident_id`)를 스크립트로 수행 — 실측 확정.

### 2.3 SKIP 집계 재검증 — 분모 오류·이중 집계 아님·"몰림" 해석 오류 ✅ B 정확(일부)

정확한 재집계 (decisions_json 전수 파싱, `{"user": {...}, "assistant": {...}}` 구조):

| 지표 | 3차 보고서 | **실측 (4차)** |
|---|---|---|
| 발화 단위 총계 | 339 (턴 수와 혼용) | **680** (user 340 + assistant 340) |
| user SKIP | 126/339 (37.2%) | **126/680 (18.5%)** |
| assistant SKIP | 40/339 (11.8%) | **40/680 (5.9%)** |
| SKIP 합계 | 166 | **166** ✓ |
| 경계 구간 0.6~0.8 | 62건 (37.3%) | **57건 (34.3%)** — 0.6~0.7: 20 / 0.7~0.8: 37 |
| 0.9~1.0 | 104건 (62.7%) | **61건 (36.7%)** |
| conf < 0.6 | — | 5건 (assistant 전수, 10-01·10-03) |

판정:
1. **분모 오류**: "user SKIP 126/339"의 분모 339는 턴 수. 발화 단위 분모는 680. **18.5%가 정확** (3차 "37.2%"는 단위 혼용 표현).
2. **assistant SKIP 40 = 턴 단위 skipped 40은 우연 일치, 이중 집계 아님**: 턴 skipped 40건의 decisions_json을 전수 대조 → 전부 user SKIP 포함(40/40), assistant SKIP 포함은 18건. assistant SKIP 40건 중 22건은 턴 단위 `stored`에서 나온 것. **수치 동일은 우연** — B의 "이중 집계 가능성"은 실측으로 **기각**되었으나, 표현상 혼동 유발은 사실이므로 재집계 방식 명시 필요.
3. **"37.3% 경계 몰림"은 해석 오류**: SKIP에서 0.6~0.8이 34.3%로 KEEP의 23.7%(80/338)보다 높긴 하나, **최다 구간은 0.9~1.0 (61건, 36.7%)** — "경계선 부근 몰림"이라는 3차 해석은 사실과 다름. B의 "기준 분포 없이는 판정 불가" 지적 확정. 0.8~0.9 / 0.9+ 분할 + KEEP conf 분포 병기로 정정.
4. **09-29 pi-test 오염 실측 확인**: `agent='pi'` 37건 전부 09-29 (skipped 26, stored 11). hermes만 재집계 시: user SKIP 93 (9+16+50+18), assistant SKIP 36 (7+27+2) = **실사용 SKIP 129건**. B 지적 정확.

### 2.4 **신규 발견 — user SKIP & assistant KEEP 108턴** (B의 단답 유실 가설 실측 성립)

(keep_user, keep_assistant) 패턴 전수: `(T,T)=192, (F,T)=108, (T,F)=22, (F,F)=18`
- **108턴이 "user는 SKIP, assistant는 KEEP"** — user의 발화가 게이트에서 걸러졌지만 같은 턴의 assistant 답변은 저장된 경우. B의 "사용자의 단답 확정('응, 그걸로')이 이렇게 사라질 수 있다"는 가설이 **실측으로 성립**.
- 이 108턴은 인접 assistant 행에 맥락이 남아 있어 **사후 정성 검토 표본**으로 즉시 사용 가능 (B 제안 채택).
- (F,F) 18턴 = user·assistant 둘 다 SKIP — 턴 단위 skipped 40건에 포함된 고위험군.

## 3. 실측 검증 — C의 지적 4건 (전부 확정/채택)

### 3.1 Recall@3 = Hit@3 (단일 gold) ✅ C 정확
scratch_items.json 실측: **180쿼리 전부 단일 gold** (multi-gold 0건). 단일 gold에서 Recall@3는 Hit@3과 동일. → metric 정의 분리 필수: **single-gold: Hit@3 / multi-gold: GoldRecall@3 = top-3 중 회수 gold 수 / 전체 gold 수**. 다중 gold 40 추가 계획과 정합 (다중 gold에서만 진짜 recall 신호).

### 3.2 probe 성공 기준 보강 ✅ 채택
payload 170KB ≠ prompt token 수 (metadata header + 120자×1,424 excerpt 포함 시 context가 진짜 제한). 성공 기준 확장: **request accepted + 전체 1,424건 score 반환 + score 누락 0 + truncation 없음 + parse 성공 + timeout 없음**. 실패 시 300×5 청크 + sentinel drift → drift 시 concat 금지, chunk top-k → 2차 rerank (별도 시스템으로 기록).

### 3.3 137행 proxy 명칭 ✅ 채택
"SKIP regret audit pilot" → **"rejudge-SKIP proxy audit"** (표 제목에 고정). §2.2 실측으로 명칭의 정확성 확인.

### 3.4 full-corpus 0.612는 "기대치 아님" ✅ 이미 기반영
3차 보고서가 이미 "기대치 아님"으로 수정한 상태 — 유지 확인. 관측값으로만 보고.

| 항목 | B 주장 | 재검산 | 판정 |

## 5. 4단계 선행 조건 3건 (B) — 전부 채택

### 5.1 독립 홀드아웃 + 무답 세트를 4단계 앞으로
- 3차 요청서 §1-7이 "운영 90은 dev/test 미분리"를 이미 명시했으나 §10 실행 순서에 **홀드아웃 구축 항목 자체가 없음** — B 지적 정확.
- **수정**: 4단계 앞에 "①운영 90 → dev/test 분할 (또는 신규 독립 세트) ②무답 dev/test 분리 (≥50~100)" 단계 신설. **무답 오주입률·오기권률이 공동 1차 지표인데 τ 보정이 4단계 뒤(5단계)인 순서 역전 해소** — τ 보정을 probe 직후·본실험 전으로 이동.
- 합성 세트(kodialog/kosgd 편향) + 운영 90(튜닝 재사용)만으로는 채택 기준("독립 홀드아웃 +5pp") 충족 불가.

### 5.2 표본·가드레일 수치 정합 (표 ≥60 vs 실행 40)
- 3차 표 "다중 gold 부분집합 ≥60" vs 실행안 "40 추가" — **수치 통일 필요** (B). 다중 gold 40 + 전체 ≥300 목표로 정리.

### 5.3 primary 비교 + 사전 등록
- **1차 비교 1개로 고정: A vs C (RRF+choice vs RRF+pointwise)** = judgment formulation effect (C).
- A vs B (retrieval fusion effect)는 2차 pre-specified, **D는 exploratory** — Holm correction도 3쌍(또는 2쌍)으로 축소.
- fusion 축은 −0.027 (약 5쿼리) 차이 — 이 표본으로 판정 불가. **C: 사다리·fusion은 탐색적 분석으로 명시**.
- 분석 스크립트+임계값을 **데이터 접촉 전 커밋 해시로 고정**, "비결정적이면 A 유지"를 파일에 명문화 (B·C 공동).

**이번 라운드의 결정**: 실행 단계 진입 확정.
