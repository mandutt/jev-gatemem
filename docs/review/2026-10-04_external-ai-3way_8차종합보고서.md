## 2. c AI 제기 → raw로 실측 검증 완료 (2건)

### 검증 1: "op 0손실"의 실체 — 게이트가 아무것도 차단 안 함 ✅ c AI 정확

`exp7h_op_gate_raw.json`의 gate NO 5건의 score:
```
498bb204 (rank1): 0.57 | b5f5672a (rank4): 0.87 | 09547ea4 (rank5): 0.88
edf486fa (rank18): 0.89 | 3581b9a3 (rank None): 0.67
```
**전부 ≥ 0.5 → R2 θ=0.5에서 모두 재주입 → op 80건 중 게이트 실제 차단 0건**

→ "A+게이트 = A (80.0%)"는 **게이트 효과가 아니라 score bypass의 결과**. 
   "게이트가 정확도를 보존"했다기보다 "이번 80건에서는 NO 판정이 전부 무효화"됨.
   **Winner Gate가 positive query의 precision을 높인다는 증거는 아직 없음.**

### 검증 2: R2 score가 winner-specific이 아님 ✅ c AI 정확 (구조적 문제)

- `run_exp7h_op_gate.py`: R2 score = `diag6_op_scores.json`의 **max_score (pool 내 최대 pointwise)**
- winner(choice 선택)의 점수와 다른 후보의 점수일 수 있음 — **winner 무관 후보의 높은 점수로 NO를 뒤집는 구조**
- 실험 5건은 우연히 일치했지만 **불변식이 아님** → 프로덕션 규칙은 **`winner_pointwise_score`** 필수

## 3. b AI 제기 — 추가 실측 검증 필요 항목

### 3.1 noans 가드레일: A 단독도 충족 (게이트 효과 과장)

- noans 해로운 오주입: **A 단독 1/50 (2.0%) (사람 판정)** vs 게이트 0/50 — 1건 차이, Wilson 겹침
- 표의 "12.0% → 4.0%"는 둘 다 **선택률** (게이트 후 남은 2건도 사람 VALID)
- → §4 비교표의 "noans FP 12.0% vs 4.0%"는 **게이트가 위반을 해소한 것처럼 보이게 하는 지표 혼합**

### 3.2 noans 6건 사람 판정 라벨이 엉뚱한 메모리에 붙었을 가능성

- 43건 판정 중 noans 6건은 **pointwise top1 대용 후보** 기준 → 실제 A 선택과 3건 다름 (⑧ 발견)
- ✅ 단, **exp7i에서 choice 실제 선택으로 재실행했지만, 사람 VALID/PLAUS 라벨은 여전히 옛 대상 기준**
- pool 재현 4/6 일치 (2건 1개 차이) — **선택 인덱스 복원은 앞 위치 1개 차이만으로 다른 메모리 복원됨**
- → **Q3: (c) 선택 id 저장 후 같은 스냅샷에서 재실행 (약 230콜) 이 맞음**

### 3.3 평가자 1인 + 기준 문서화 부재

- 게이트 NO + 사람 VALID 불일치 18건 — "게이트가 엄격" vs "사람 VALID 기준이 느슨" 구분 불가
- 사람이 느슨했다면 해로운 오주입률 5.6%는 과소평가
- → **맹검 재판정 또는 2차 평가자** 권고 (b)

### 3.4 더 큰 레버: 선택 단계(A)의 120자

- 게이트는 A가 고른 winner만 봄 — **A가 120자 절단으로 놓친 근거는 게이트가 구제 불가**

| AI | 판정 | 근거 |

| a | (a) 800자 적절 | p50 340자, 한국어 800자 = 대화 3~4턴, 1,500자는 대역폭 낭비 |
