# 게이트 지연 최적화 실측 — 동시 발사(B) 채택 + 게이트 드리프트 발견 (2026-10-05)

## 요약

- 목적: 8차 남은 과제 3 — "게이트를 choice와 병렬/동일 요청으로 묶는 방안"
- C(동일 요청 2질문): **systemone 1요청 1질문 하드 제약으로 400 — 기각** (7차 Q5의 "다중 yes/no 1요청" 아이디어도 이 제약으로 원천 불가)
- B(동시 발사): gate 지연 p50 **400ms** → 동시 발사 예상 p50 **536ms** (직렬 1,271ms 대비 **-58%**), p95 3.4s → ~1.6s
- **채택**: 병렬 도입 — 단, 일치율 90.9%는 사전 기준(≥95%) 미달이나 **병렬이 원인이 아님을 실측으로 증명**

## 실측 결과

| 방식 | 동작 | 판정 | 지연 p50 |
|---|---|---|---|
| A. 직렬 (현행) | choice → winner → gate | 기준 | ~1,271ms |
| B. 동시 발사 | choice+gate 병렬 (max) | exp8e 대비 90.9% (140/154) | **~536ms** (-58%) |

- 불일치 14건: 전부 **YES→NO 단방향**, winner_score 0.56~0.81 (9/10 < 0.8 = 경계 사례)

## 통제 실험: 불일치 14건 순차 재호출

- 12/14가 **여전히 NO** — 병렬 탓이 아니라 **게이트 판정 자체의 드리프트** (같은 입력, 시간 경과에 따라 YES→NO)
- exp8e 내부에도 중복 qid 43건 (같은 쿼리 반복 실행) — Jev 비결정성 + 드리프트가 원래 존재

## 결론

1. **B(동시 발사) 채택**: 병렬로 인한 추가 판정 손실 0 (직렬 재호출도 동일 14건 NO). 지연 -58%는 실질 이득.
2. **C 기각**: API 하드 제약 (1요청 1질문).
3. **★ 진짜 발견: 게이트 드리프트** — 같은 winner/입력이 시간에 따라 YES→NO로 단방향 이동. exp8e(9/04) 대비. 이건 shadow enforcement 판정에 직접 영향 — **같은 쿼리 반복 측정으로 드리프트를 감시해야 함**.
