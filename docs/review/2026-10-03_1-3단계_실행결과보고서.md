## 2. 1단계 — 인프라 구현

### 2.1 skip_shadow (shadow logging)
- `jev_mem_core/ledger.py`: `skip_shadow` 테이블 신설
  - UNIQUE `idem_key` — 동일 SKIP 이벤트 중복 기록 방지
  - **1,500자 cap** (한글 3바이트 고려; 1KB 바이트 cap은 ~340자로 기각)
  - TTL 90일 인덱스
- `jev_mem_core/pipeline.py` → `_shadow_skips()` (Pipeline 클래스 메서드):
  - SKIP 턴만 shadow 기록, KEEP 무시
  - UNIQUE 충돌 시 무시 (fail-open 아님)

### 2.2 query_log
- `core_state.db`에 `query_log` 테이블 — prefetch 쿼리 영속 로깅
- recall 경로 무영향 (audit-only)

### 2.3 _jev_client EXPERLABS 전환
- `EXPLABS_API_KEY` 우선 + `JEV_API_URL=https://api.experientiallabs.ai/v1/systemone`
- TYPESAFE fallback 유지
- **실측**: `_jev_client` 인증 OK / `jev_rerank` deadline 질문에서 bbb→#1 lift (1,287ms) / query_log 기록 정상

### 2.4 과정에서 수정한 버그
1. `_shadow_skips` 클래스 메서드 스코프 복구 (들여쓰기 함몰로 후속 메서드가 함수 바디에 갇혔던 문제)
2. `json` import 누락 (조용한 NameError → shadow 0건의 원인)
3. `_jev_client`가 typesafe 전용 클라이언트를 호출하던 문제 → EXPERLABS 직접 인식

## 4. 3단계 — probe 실측 (EXPERLABS)

### 4.1 probe ①: 단일 쿼리 대형 배치 기능 확인

| 지표 | 값 |
|---|---|
| 코퍼스 | 1,310행 / 1,136,599자 |
| 질문 수 | 1,395 (chunks 8,000자) |
| 배치 | 44 × 32질문 |
| 지연 | **4.9초** (병렬 8) |
| score 수 | 1,310/1,310 (고아 0) |
| 실패 | 0/44 |
| score 범위 | 0.010 ~ 0.960 |
| **판정** | **PASS** |

**핵심 발견 — 32질문 한도**: EXPERLABS는 요청당 질문 수 ≤32만 허용 (n=32: 200, n=35: 400 `Invalid decision request`). PR `fanout`의 48KB 바이트 배칭은 EXPERLABS에서 질문 수 제한을 위반해 400 발생 → **직접 32질문 단위 배칭으로 대체**.

### 4.2 probe ②: 10회 반복 성능·지연·비용

| 구성 | 총 지연 | 평균/회 | 실패 | 질문/초 |
|---|---|---|---|---|
| 병렬 8 | 32.7초 | 3.3초 | **286 배치 (429 rate limit)** | 415 |
| **병렬 2 + 2초 대기** | **161.3초** | **14.3초** | **0** | 84 |

- 병렬 8: round 4부터 429로 붕괴 (rate limit)
- **병렬 2 + 2초 대기: 10회 전부 무실패 (PASS)**
- score 범위 안정 (0.010~0.960)

**핵심 발견 — rate limit**: EXPERLABS는 동시성에 취약. 병렬 8 = 429, 병렬 2 + 지연은 안정. 실서비스(jev_rerank, 수십 질문)는 무영향, 벤치마크 대량 실행 시 **병렬 2 + 지연 기본 권장**.

### 4.3 probe ③: 배치 분할 불변성

## 5. 종합 결론

### 5.1 EXPERLABS 게이트웨이 실측 특성
1. **32질문/요청 한도** — 초과 시 400
2. **rate limit** — 병렬 8은 429, 병렬 2 + 2초 대기는 안정
3. **결정론적 점수** — std 0.0018, drift 0.01 (5회 반복)
4. **threshold 결정 안정** — 분할·반복에 KEEP/REJECT 불변
5. **모델 고정** — `jev-latest`만 허용 (jev-1.13.0 → 403)

### 5.2 jev-mem 아키텍처 실증
- **write-time gate + read-time 1-call Jev rerank**는 EXPERLABS 실게이트웨이에서 정상 동작
- 대량 벤치마크는 병렬 2 + 32질문 배치 권장 (비용: 전체 코퍼스 1회 ~1,395질문 ≈ 44요청)
- **regret 0%** (103건 전수 정성 검토) — SKIP 감사 프로토콜의 실효성 입증

### 5.3 4차 보고서 대비 수정
| 항목 | 4차 보고서 | 본 실측 |
|---|---|---|
| 코퍼스 크기 | 1,424행 | **1,310행 (핫 행만)** |
| 배치 방식 | PR fanout 48KB | **32질문 단위 직접 배칭** |
| 동시성 | (명시 없음) | **병렬 2 + 2초 대기 권장** |
| rate limit | (미검출) | **429 — 병렬 8에서 실측** |
| score 안정성 | (미검증) | **std 0.0018 결정론적** |
