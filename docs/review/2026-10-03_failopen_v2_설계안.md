## 1. 상태 머신 (C-AI 제안 채택, ledger 상태 확장)

```
                    JEV 정상 판정
   received ───────────────────────► stored / skipped
        │
        │ JEV 판정 불가 (http-4xx/no-key/error 등)
        ▼
   fail_open_quarantine ──(JEV 회복 감지)──► rejudge_pending
        │                                        │
        │ (재판정 자체 실패)                      ▼
        └──────────── rejudge_failed ◄───── rejudge_running
                                                     │
                                          ┌──────────┴──────────┐
                                          ▼                     ▼
                                   rejudge_kept           rejudge_invalidated
                                   (정상 승격)            (SKIP, recall 제외)
```

- `fail_open_quarantine`: JEV 판정 실패로 **저장은 됐지만 quarantine** — 재분류 대상
- `rejudge_*`: 재판정 파이프라인 상태 (배치 단위, lease 포함)
- `rejudge_failed`: 재판정 중 JEV 재실패 → quarantine 유지 (원문/본문 보존)

**불변식 (D2, C-AI 핵심)**:
```
IF availability == UNAVAILABLE AND decision == KEEP
THEN preservation == QUARANTINE
```
즉 allowlist 폐기: **"정상 판정(JEV 응답 후 규칙 판정)이 아닌 모든 KEEP은 quarantine"**

## 2. 에러 분류 taxonomy (C-AI)

```
GateResult {
  decision       = KEEP | SKIP
  availability   = AVAILABLE | UNAVAILABLE
  failure_class  = NONE | BILLING | AUTH | TRANSIENT | PARSE | CONFIG | UNKNOWN
  retry_policy   = NONE | PROBE | BACKOFF
  preservation   = NORMAL | QUARANTINE
}
```
- `BILLING`(402)·`AUTH`(401/403): retry_policy=NONE (지속적), preservation=QUARANTINE
- `TRANSIENT`(5xx/429/timeout): retry_policy=BACKOFF (기존 pending_gate 유지), 상한 초과 시 QUARANTINE 전환
- http status → class 매핑은 **한 곳에 집중** (write_gate), reason 생성과 분류 분리 제거

## 3. 재판정 파이프라인 (D3, D4)

### 3.1 회복 감지 (서킷 브레이커 + 프로브, B·C)
- N회 연속 UNAVAILABLE → circuit open → **호출 중단** (헛호출 방지 — 이번 94회 실측)
- 주기 프로브: **실제 systemone 판정 호출**로 회복 확인 (단순 /v1/status 아님)
- **연속 성공 N회(≥3) + M분 유지** → half-open → closed (플래핑 방지 히스테리시스)

### 3.2 재판정 엔진
- 격리 대상: `fail_open_quarantine` 인 **incident batch** 단위 (`incident_id` = 장애 구간 start~end)
- 입력: **저장 본문 전체** (실측 ②: 저장본 == gate 입력, redaction 적용본) — `[:1500]` 선절단 금지
- **strict 모드**: JEV 실패/파싱 실패 시 예외 → `rejudge_failed` (행·마커 불변)
- 결과 기록 (D-3 보강): `rejudged_at`, `verdict`, `model_version`, `gate_version`, `reason`, `latency`
- **KEEP 승격은 자동** (비파괴), **SKIP invalidation은 수동 승인** (파괴적) — B·C 합의

### 3.3 SKIP 처리 (D5)
```
rejudge_invalidated → recall·FTS·vec·graph 4개 lane에서 제외
                     → consolidation lineage 확인 (summary_of)
                     → 30일 후 hard delete (또는 사용자 purge)
```
- row는 삭제하지 않고 `metadata.gate = rejudged:skip` + `archived` 플래그
- **lineage**: episodic.summary_of가 working_memory ID를 가리키는지 확인 → 흡수 시 요약도 재생성 대상

## 4. 감지·경보·운영 (D7 — B가 가장 중요 지적)

- **402 = "충전 필요" 배너/알림** 명시 (데스크톱 + /v1/status)
- 장애 구간 기록: `gate_outage(incident_id, start, end, reason, count)` 테이블
- `/v1/status` degraded가 마커에 의존하던 문제 → **failure_class 기반으로 독립 집계**
- 재판정 마커 이력 보존: `fail_open:http-402` → `rejudged:keep@<model>/<date>` (지우지 않음)
- 읽기 측 장애(choice 403)도 recall 폴백 구간 기록

## 5. recall 정책 (D6)

- quarantine 메모리: **기본 보조 lane** (정상 pool 먼저, 부족 시 참여) — 완전 배제 아님
- `JEV_FAILOPEN_HIDE=1` 비상 스위치 (기본 OFF) — 완전 필터
- 사용자 "보관 의미 유지" 입장 존중

## 8. 명시적 비수용 (AI 의견 중 채택 안 함)

| 제안 | 이유 |
|---|---|
| P2 원문 별도 보존 (quarantine 테이블/TTL) | 실측 ②: 저장 본문으로 재판정 충분 — 불필요한 프라이버시 비용 |
| 가중치 하향 (A안) | 보조 lane이 더 명확 (C·B), 4-lane 수정 비용 |
| 402/403 → pending_gate (A안 일부) | fail-open 철학과 충돌 (C·B 합의) |
| hard delete 자동화 | risk > benefit (전 AI 공통) |
