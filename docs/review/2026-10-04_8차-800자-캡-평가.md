## 3. 결론

### 3.1 현재 운영에서 800자 캡 손실 = 0 (실측)

- choice가 winner로 고르는 메모리는 전부 800자 이하
- 800자 초과 후보는 어차피 무관 (choice가 고르지 않음)
- 정답 후보도 800자 이하

### 3.2 그러나 미래 안전장치로 window 방식 채택

b/c AI의 지적은 **미래 시나리오**에서 타당:
- 코퍼스가 성장하며 긴 메모리(로그)가 winner가 될 가능성
- head-only는 잘린 꼬리에 답이 있으면 오판 (⑥에서 이미 경험)

**권고: head+tail window (head 600 + tail 200 = 800자)**:
```python
def cap_window(text, limit=800):
    if len(text) <= limit:
        return text
    head = text[:600]
    tail = text[-200:]
    return head + "\n...[중략]...\n" + tail
```
- head 600: 앞부분의 핵심 사실 보존
- tail 200: 잘린 꼬리의 답 보존 (⑥ 교훈)
- 추가 토큰 부담 0 (캡 유지)

### 3.3 full-text 무제한 대비

| 방식 | 토큰 (max) | 손실 위험 | 채택 |
|---|---|---|---|
| head-only 800 | ~560 | tail 답 손실 | ❌ (미래 위험) |
| **head+tail 800** | **~560** | 최소 | ✅ |
| full-text | 75K+ | 0 | ❌ (토큰 폭탄) |
