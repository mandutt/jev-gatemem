## 0. 결론 요약 (한 문단)

**0.556 vs 0.806 격차는 "시스템 품질 차이"가 아니라 "평가 조건 차이"였다.** PerfectRecall은 후보 5개 중 1위를 측정했고, 내 파이프라인 평가는 풀 55개 중 1위를 측정했다. 같은 스코어러·같은 쿼리·같은 풀에서 반복 실측한 결과: (1) 27건 판정 차이는 3회 반복에서 전부 동일 순위의 **결정적 실패** (비결정성 아님), (2) 그러나 같은 쿼리를 **cands 5개만으로 판정하면 12/12 전부 1위**, (3) 사실형 데이터셋(koalpaca, machinereading)은 **PR과 내 파이프라인 모두 100% 동률**. 격차 43건 중 40건이 kodialog(대화 단답 5-way 선택 태스크) 단일 데이터셋에서 나왔다.

### 2.3 판정 차이 27건의 실체 (Run C + Run E)

- 3회 반복: 27건 **전부 동일 순위** — 비결정성 0건, 동점 0건 (완전 결정적)
- 풀 내 정답 순위: 2~16위 분산 (평균 ~8위)
- **같은 쿼리를 cands 5개만 판정: 12/12 전부 1위** (Run E, 무작위 12건 샘플)

→ **스코어러 품질 차이가 아니다.** 풀(55)에는 cands(5)보다 "그럴듯한 대화 후보"가 50개 더 있고, 정답이 이들에게 밀릴 뿐이다. PR 평가는 5-way, 내 평가는 55-way — **측정하려던 것 자체가 달랐다.**

### 2.4 Run D: 419 전체 스캔 직접 재현 (8건 샘플)

419 스캔 시 정답 순위가 풀보다 **더 나빠졌다** (예: idx0 풀 14위 → 419 58위). PR 기록(0.806)과 모순되었으나, 원인은 PR의 rank 계산이 "cands 안에서의 순위"였기 때문 — 419 점수를 cands 5개에만 적용해 비교한 구조. 즉 **PR의 우위는 스캔 범위가 아니라 판정 후보를 5개로 제한한 데서 온다.**

## 3. 최종 결론

1. **0.556 vs 0.806은 비교 불가능한 두 지표였다** (55-way vs 5-way). 동일 조건 비교 시:
   - 사실형(koalpaca, machinereading): **양측 100% — 격차 없음**
   - kodialog 5-way 조건 재현 시: 내 스코어러도 **100% (12/12)**
2. **"스캔 범위 효과" 가설 기각.** "전체를 보면 정답이 두드러진다"는 설명 불필요. 후보를 좁게 주면(5개) 판정이 쉬워지는 것.
3. **풀 내 판정 차이 27건은 kodialog의 5-way 태스크 특성** — 정답이 "화용론적 단답"이라 의미적 함의가 0이고, 유사 대화 후보가 다수 존재하는 상황에서의 근본 한계. 운영 메모리(Hermes 코딩/설정/선호)에는 이 유형이 드물다 (라이브 DB <50자 16.4%, 대부분 기술 팩트).
4. **시스템 구조(a8m + RRF + 완화 게이트 + POOL 40 + JEV choice)는 유효하다.** 구조 개편 근거 없음.

## 4. 합의된 다음 단계 (3개 AI + 실측 종합)

1. **POOL_BUDGET 확대 금지 확정** — 이득 9~13건 전부 kodialog 소속, 운영 가치 0
2. **운영 평가셋 구축** (유일하게 남은 미측정 영역):
   - 60문항 시작, 지표: **hit@5 + MRR + Top-40 Pool Recall + 무답 오주입률 + 갱신 쿼리 최신성** (Acc@1 단일 금지)
   - 실패 모드 축: 의역 30% / 갱신·모순 10% / 무답 15%
   - 다중 정답 허용 (Primary + Acceptable)
   - 변형 비교용이 아니라 회귀·실패모드 발견용 (변형 비교 시 100~150문항 필요)
3. **합성 벤치**: 튜닝 종료, **회귀 테스트로 유지** (게이트 결함을 잡아낸 실적)
4. 무료 레버 (운영셋 구축 후 검토): 후보 텍스트 절단(150~200자) 시 토큰 절감, Score Calibration (S_jev + α·S_vec)
