### 2.4 Run D: 419 전체 스캔 직접 재현 (8건 샘플)

419 스캔 시 정답 순위가 풀보다 **더 나빠졌다** (예: idx0 풀 14위 → 419 58위). PR 기록(0.806)과 모순되었으나, 원인은 PR의 rank 계산이 "cands 안에서의 순위"였기 때문 — 419 점수를 cands 5개에만 적용해 비교한 구조. 즉 **PR의 우위는 스캔 범위가 아니라 판정 후보를 5개로 제한한 데서 온다.**

## 3. 최종 결론

1. **0.556 vs 0.806은 비교 불가능한 두 지표였다** (55-way vs 5-way). 동일 조건 비교 시:
   - 사실형(koalpaca, machinereading): **양측 100% — 격차 없음**
   - kodialog 5-way 조건 재현 시: 내 스코어러도 **100% (12/12)**
2. **"스캔 범위 효과" 가설 기각.** "전체를 보면 정답이 두드러진다"는 설명 불필요. 후보를 좁게 주면(5개) 판정이 쉬워지는 것.
3. **풀 내 판정 차이 27건은 kodialog의 5-way 태스크 특성** — 정답이 "화용론적 단답"이라 의미적 함의가 0이고, 유사 대화 후보가 다수 존재하는 상황에서의 근본 한계. 운영 메모리(Hermes 코딩/설정/선호)에는 이 유형이 드물다 (라이브 DB <50자 16.4%, 대부분 기술 팩트).
4. **시스템 구조(a8m + RRF + 완화 게이트 + POOL 40 + JEV choice)는 유효하다.** 구조 개편 근거 없음.

## 4. 합의된 다음 단계 (3개 AI + 실측 종합)

1. **POOL_BUDGET 확대 금지 확정** — 이득 9~13건 전부 kodialog 소속, 운영 가치 0
