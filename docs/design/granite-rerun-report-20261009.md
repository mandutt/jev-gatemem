# Granite R2 재실측 + 전 모델 X1 최종 비교 보고서 (2026-10-09)

> 상위 문서: `embed-benchmark-final-report.md` (S1~S3, bekko 채택), `experiments/embeddinggemma2-eval/README.md` (EmbeddingGemma 2 stage74~82)
> 이 보고서는 2026-10-09 텔레그램 세션에서 수행한 **granite-97m-r2 재실측**과 **전 모델 동일 조건 X1 비교**를 다룬다.

---

## 1. 배경 — 왜 재실측했나

- 2026-10-01 S2 실측에서 granite-97m-r2는 정적 quint8 배치 64 **무한 hang** → 배치 4 사후탐색에서 **50.8GB 버퍼 OOM** → "운영 불가 확정" 판정 (사용자 지시로 재시도 없음).
- 2026-10-09, wikidocs 블로그(13528, "IBM Granite Embedding R2, 97M 파라미터로 300M급 모델을 이긴다")에서 granite의 CPU 배포 가능성 강조 → 재검토 요청.
- **원인 재분석 결과**: 2026-10-01 사후탐색은 **클램프 512 미적용** 상태였다. 토크나이저 상한 32,768토큰 그대로 10만 자 문서가 통째로 들어가 attention 버퍼(batch × L²)가 폭발. 동일 ModernBERT 계열인 bekko는 클램프 512로 해결된 바 있음 → **"운영 불가"는 절차 오류(계획 이탈)로 인한 과잉 판정**으로 판단.
- q4f16 변형(148MB, cos 0.99급, yuiseki ONNX)도 후보에 추가 — int8(cos 0.955) 드리프트 우려 때문.

## 2. Phase A — 변형별 스모크 + 예비 드리프트 (2026-10-09)

환경: Windows 11, R5 7600, RAM 15.6GB, CPU, jev-mem venv (ORT 1.30.0, fastembed 0.8.1), 클램프 512 적용 확인.

| 변형 | 로드 | RSS (cold/warm) | 단건 지연 | 클램프 | 문장 cos (f32대비) | top-10 겹침 |
|---|---|---|---|---|---|---|
| **fp32** (390MB) | 1.04s | 537/540MB | 6.6ms | 512 ✓ | 기준 | 기준 |
| **q4f16** (148MB) | 0.83s | 307/311MB | 15.5ms | 512 ✓ | **0.9854** | **0.82** (min 0.7) |
| quint8 (98MB) | 0.82s | 247/250MB | 4.9ms | 512 ✓ | 0.956 | ~0.8 |
| int8 dynq (98MB) | 0.81s | 245/250MB | 4.1ms | 512 ✓ | 0.9553 | **0.66** (min 0.6) |

- **int8·quint8은 예비 드리프트(≥0.90) 미달 → 풀 테스트 제외** (특히 int8: cos 0.955, 겹침 0.66 — yuiseki 경고 "int8 드리프트 큼"이 검색까지 재현).
- **q4f16, fp32만 Phase B 진행.** 클램프 512 적용 확인 — 이번엔 절차 정상.

## 3. Phase B — 풀 테스트 (재인덱스 + gold-50 + 드리프트)

| 메트릭 | **granite-fp32** | **granite-q4f16** |
|---|---|---|
| 재인덱스 1,143건 (clamp512, batch4) | **50.7s** | **49.8s** |
| gold-50 MRR | 0.550 (R@1 0.48 / R@10 0.70) | **0.570** (R@1 0.50 / R@10 0.72) |
| 드리프트 (fp32 대비 top-10, 30쿼리) | 1.00 (자기대조) | **0.83 평균 / 0.30 최저** |
| RSS (warm) | ~540MB | ~311MB |

- **granite은 클램프 512만 걸면 완전 운용 가능** — 과거 "운영 불가 확정" 철회.
- q4f16 gold-50 MRR이 fp32보다 근소 높음 (50쿼리 노이즈 내 동급). 드리프트 0.83(min 0.3)은 검색 순위가 fp32와 상당히 다르게 움직임을 의미 — 품질은 gold로는 동급이나 "동일 결과 보장"은 아님.
- 재인덱스 50s는 bekko(807s @batch4)의 **16배 빠름** (granite attention이 로컬 슬라이딩 윈도우라 실연산량 작음).

## 4. X1 외부 데이터셋 실측 (KoDialogBench, 1,200문항, 동일 조건)

### 4.1 granite fp32 / q4f16 (신규)

| 모델 | Acc@1 | MRR | 임베딩 시간 |
|---|---|---|---|
| granite-fp32 | 0.557 | 0.720 | 64s |
| granite-q4f16 | 0.541 | 0.713 | 72s |

### 4.2 EmbeddingGemma 2 q4f16 / q8 (신규 재실측, 1,200문항)

| 모델 | Acc@1 | MRR | 임베딩 시간 | RAM (warm commit) |
|---|---|---|---|---|
| **gemma2-q8** (314MB) | **0.690** | **0.813** | 1301s (~22분) | **466MB** |
| gemma2-q4f16 (157MB) | 0.683 | 0.806 | 888s (~15분) | 559MB |

- 서브코퍼스 (q8): dailydialog 0.743 / empathetic 0.750 / personachat 0.577 / socialdial 0.690 — 4개 전부 1위.
- **q8이 q4f16보다 품질 근소 우위·RAM 작음(466MB, q4f16 559MB > q8!)** — "파일 크기 ≠ RAM" (q4f16은 활성화 fp16 유지로 중간 버퍼 큼, README §2.1 재확인).
- **q8이 더 느림 (1301s vs 888s)** — 314MB int8+dequant 연산이 4-bit보다 무거움.

### 4.3 전체 순위표 (X1 1,200문항, 동일 러너·클램프·시드)

| 순위 | 모델 | Acc@1 | MRR | 임베딩 시간 |
|---|---|---|---|---|
| 1 | **gemma2-q8** | **0.690** | **0.813** | 1301s |
| 2 | gemma2-q4f16 | 0.683 | 0.806 | 888s |
| 3 | koen | 0.622 | 0.758 | 40s |
| 4 | baseline | 0.587 | 0.741 | 37s |
| 5 | bekko-a8m | 0.583 | 0.737 | 19s |
| 6 | granite-fp32 | 0.557 | 0.720 | 64s |
| 7 | granite-q4f16 | 0.541 | 0.713 | 72s |

### 4.4 해석

- **gemma2가 외부 도메인(대화 응답 선택)에서 압도적 1위** — 2위 koen +0.068, 현행 bekko +0.107. 이전 400문항 실측(0.535 vs bekko 0.443)이 1,200문항에서 재현·확대.
- 기존 README §2.6 패턴 재확인: **내부 gold(어휘 중복 편향)에서는 bekko 1위(0.772), 외부 의미 검색에서는 gemma2 1위** — "모델의 진짜 품위는 도메인에 의존".
- granite은 둘 다 중위권 — 공개 MTEB 60.3(최고)은 우리 도메인에서 미재현.

## 5. MRL 256 절삭 속도 프로브

- gemma2 q4f16으로 32문장, 768d vs 256d(절삭) 임베딩 시간 실측: **56.2 vs 57.7 ms/vec — 차이 없음 (오히려 +3.5% 노이즈)**.
- 결론: **MRL 절삭은 모델 실행 후 슬라이싱 — 임베딩 속도 무관. 256의 이점은 저장 공간 1/3·벡터 검색 경량화뿐** (우리 규모에선 체감 미미). 속도 향상은 스레드/배치/모델 축에서만 가능.

## 6. 최종 판정 요약

| 모델 | 내부 gold-50 MRR | X1 Acc@1 | RAM | 재인덱스 | 비고 |
|---|---|---|---|---|---|
| **bekko-a8m (현행)** | **0.772** | 0.583 | 617MB | 807s | 속도 최강 p95 1.5ms |
| granite-q4f16 | 0.570 | 0.541 | **311MB** | **50s** | 최경량·스키마 유지(384d) |
| gemma2-q8 | 0.739(이전) | **0.690** | 466MB | ~31분 | 외부 품질 1위·768d 스키마 전환 필요 |

- **granite "운영 불가" 판정 철회** — 클램프 512 조건에서 완전 운용 가능 + 최경량 + 최속 재인덱스.
- **gemma2-q8 외부 품질 1위 확정** — 단 768d 스키마 마이그레이션 + 속도 비용.
- **최종 채택은 사용자 우선순위 몫**: 품질(외부) = gemma2-q8 / 경량·무마이그레이션 = granite-q4f16 / 현행 유지 = bekko.
