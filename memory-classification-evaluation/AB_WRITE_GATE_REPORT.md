- **A (현재)**: rule 분류기 + 무조건 저장 — 142건 전부 저장
- **B (JEV 게이트)**: JEV로 분류 후 SKIP 규칙 적용
- **판정**: SKIP 후보를 사용자가 🟢skip-ok(저장 불필요) / 🔴skip-bad(저장 필요)로 판정 — **83건 전량 (ok 69 / bad 14)**

## 3. 핵심 발견

### 3.1 bad 14건 = "프로젝트 기술 질문" — P8+G0.6에서 전부 KEEP ✅
```
"Type 정확도 (14종) 항목에서 jev 48.6%면 정확도가 좀 부족한 거 아니야?"   → context
"그런데 저신뢰는 가중치로 판정 가능하지만, 명사형 같은 걸 llm에 맡기는 기준은?" → context
"만약에 C안인 외부 레이어로 분리한다고 치자. 네가 예전에 설명했던 것 중에..."  → context
"'~ㄴ지' 같이 끝에서 두번째 글자 받침이 ㄴ인 경우를 므네모슈네가 인식할 수 있을까?" → NO_STORE(저신뢰)
```
- 전부 `~이야? / ~까? / ~할까?` 형태의 **코드/설계/구현 맥락 질문**
- P10부터 type이 context/instruction/decision/goal 등으로 재분류 → 게이트 통과 (KEEP)

### 3.2 G-type&store 과잉 SKIP — 실제 문제는 "너무 많이 거름"
- 83건(58.5%)을 SKIP → 그 중 14건이 실제 저장 가치 (누락 위험)
- **conf로 분리 불가**: bad avg conf 0.72 vs ok avg conf 0.76 — 거의 동일
- **문제는 프롬프트의 "질문=일회성=NO_STORE" 편향** (평가 데이터 일반 대화 기준)

### 3.3 P9/P10 과잉 교정 — "모든 질문=STORE"로 저장 필터 붕괴
- P9: "소프트웨어 작업 맥락 질문=STORE" 명시 → 저장 137건 (96%) — 과다저장 원상복구
- P10: "GO-AHEAD 진행 명령=NO_STORE" 명시 → 과다저장 완화 (특히 type 정확도 -16.5pp)
- **type 분류는 P8 유지가 정답** — 도메인 적응은 게이트 규칙에만

### 3.4 G0.6 (P8) — store 단독 게이트 + 신뢰 임계값 = 최종 채택
```
SKIP = store==NO_STORE && store_confidence >= 0.6  (type 무관)
```
- **누락 0건** (bad 14건 전부 KEEP), **저장 77%** (110건), **과다저장 11건만**
- SKIP 32건 모두 사용자 판정 ok — 오분류 0
- **원칙: JEV가 확신(conf≥0.6)할 때만 SKIP, 의심되면 KEEP (누락보다 과다저장이 안전)**

## 4. 판정 기준 불확실성 (사용자 코멘트)
