## 1. 실험 설계

- **대상**: `state.db` messages 테이블에서 role='user' 실제 발화 (메타 지시문/짧은 것/<12자 제외, 멀티라인 첫 줄) → 142건
- **A (현재)**: rule 분류기 + 무조건 저장 — 142건 전부 저장
- **B (JEV v8 게이트)**: JEV로 분류 후 `type==NO_STORE && store==NO_STORE` → SKIP, 나머지 KEEP
- **판정**: SKIP 83건을 사용자가 🟢skip-ok(저장 불필요) / 🔴skip-bad(저장 필요)로 전량 판정

## 3. bad 14건의 실체 — "프로젝트 기술 질문"

전부 `~이야? / ~까? / ~할까?` 형태의 **코드/설계/구현 맥락 질문**:

```

"그런데 저신뢰는 가중치로 판정 가능하지만, 명사형 같은 걸 llm에 맡기는 기준은?"  conf=0.77
"만약에 C안인 외부 레이어로 분리한다고 치자. 네가 예전에 설명했던 것 중에..."    conf=0.77
"므네모슈네 원본의 기록 방식과 jev 개입 기록방식 중 어떤 것이 더 나을까?"       conf=0.82
"'~ㄴ지' 같이 끝에서 두번째 글자 받침이 ㄴ인 경우를 므네모슈네가 인식할 수 있을까?"  conf=0.87
```

**왜 이런 차이가 나는가**: 
- 평가 데이터(KoDialogBench 등 일반 대화)에선 "질문/설명 요청" = 일회성 = NO_STORE
- **실제 데스크톱 작업 맥락**에선 "설계 질문/구현 상태 질문" = **프로젝트 맥락 = 저장 가치**
- JEV v8은 이 도메인 차이를 모름 → 16.9% 누락 위험

**결론**: conf 임계값으로는 해결 불가 (bad/ok conf 동일). **도메인 적응 프롬프트** 필요:
> "코드/설계/구현 작업 맥락의 질문(설계 대안, 아키텍처, 버그 원인, 상태 확인)은 일회성이 아니라 저장 가치가 있다. NO_STORE는 잡담/일회성 요청/감사/진행 명령만."

## 5. 판정 기준 불확실성 (사용자 코멘트)

> "선택하면서도 내 스스로의 기준에 확실했는지는 사실 자신이 없어"

- 실제로 bad 14건 모두 **한결같은 패턴**(기술 질문) — 사용자 판정이 일관적이었음을 반증
- 다만 "이건 저장해야지"의 기준이 **문맥 의존**(그 시점의 작업)이라, 같은 발화도 상황 따라 다를 수 있음
- → **정밀한 측정보다 "패턴 식별"이 이 A/B의 진짜 산출물**

## 6. 권고

1. **JEV v8 + 도메인 적응 프롬프트(v9)로 재실험** — bad 14건이 잡히는지 확인
2. **게이트는 SKIP 기준을 "type==NO_STORE && store==NO_STORE && type_confidence≥0.6"으로** — 저신뢰 NO_STORE는 KEEP (보수적)
