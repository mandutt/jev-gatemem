# Run L — PerfectRecall 방식(전체 스캔) × 운영 골든셋 (2026-10-01)

> PR 스코어러(jev relevance 배치 스캔)를 우리 운영 골든셋(90 gold + 무답 10, 동일 쿼리)에
> 그대로 적용해 Run J와 동일 조건 비교. production DB 읽기 전용, 코퍼스 1,234 스팬.

## 결과 비교

| 지표 | Run J (우리: 풀40+choice 1회) | **Run L (PR: 전체 1,234 스캔)** |
|---|---|---|
| **Acc@1** | **83.3%** (75/90) | **52.2%** (47/90) |
| hit@5 | 88.9% | **92.2%** |
| MRR | **0.946** | 0.709 |
| 정답 커버리지 | 90.0% (게이트 통과) | **100%** (풀 스캔) |
| 쿼리당 JEV 호출 | 1회 | **48회** (4,800/100) |
| p95 latency | 336ms | **1,124ms** |
| rank2 집중 | — | **28/90 (31%)가 2위** |

## 핵심 발견

1. **PR full-scan이 운영 골든셋에서 Acc@1 30%p 낮음** — 커버리지는 100%인데도.
   31%의 쿼리에서 정답이 2위에 놓임: relevance 스코어러가 1,234개 후보 사이에서
   "정답과 거의 동급의 관련성"을 가진 다른 메모리(같은 프로젝트/주제의 인접 기억)를
   1위로 밀어올림. 소규모 5-way(419 후보, PR 80%)에서는 드러나지 않던 대규모
   혼동 문제.

2. **hit@5와 MRR이 대조적**: PR이 hit@5(92.2%)에서 이기고 MRR(0.709)과 Acc@1에서
   크게 진다 — "정답을 5개 안에 넣는 능력"은 풀 스캔이 우수하나, "1위로 확정하는
   능력"은 풀 40 압축 + choice의 단일 판정 구조가 강하다.

3. **비용·지연**: 쿼리당 48회 호출, p95 1.1초 — 운영 스케일에서 실용성 한계 명확.

## 해석 (Inferred — 검증 필요)

운영 코퍼스는 같은 프로젝트/주제의 인접 메모리가 다수 존재(1,224행 중 관련 기억
군집)라, PR relevance 스코어러가 "주제는 같은데 정답은 아닌" 기억을 높게 평가.
우리 choice 프롬프트("best evidence for answering the question")는 이 구분에 더 유리.

## 결론

**동일 조건 운영 골든셋에서 우리 파이프라인(Acc@1 83.3%)이 PR 방식(52.2%)을
+31.1%p 앞섬.** PR의 LongMemEval-S 85.8%는 소규모·단답형 조건의 결과로,
운영 규모(1,224행 장문 기술 기억)에서는 역전됨. 하이브리드 필요성 소멸 —
full-scan 재현 구조는 운영에 불필요.
