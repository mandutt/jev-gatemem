# stage104 — k=2 프레이밍 페어드 실험 결과 (2026-10-10)

## 배경
- 목적: k=2 노출에서 **fF(프레이밍 없음) vs fT(프레이밍 있음)** 중 어느 쪽이 메모리 인용을 더 잘 유지하는지 통계적 검정
- 동기: stage101/102p 데이터에서 k=2+fT의 no 비율이 높아 보여 (14.4% vs 9.5%), "k=2+framing=False 최적화" 가설 검증 필요

## 방법론 (stage103→104 교훈)
- stage103 (deepcombo 생성 + haiku 판정): **ERR 응답 70건(19.4%)이 판정에 포함되는 오염** — deepcombo가 503/파싱 실패로 에러 텍스트 반환, claude가 이를 no로 판정 → no 비율 인위적 상승
- **stage104: 생성도 haiku(tokenharbor/claude-haiku-5.5:free)로 통일** — 생성·판정 동일 모델, ERR 0건
- 60개 질문 × fF/fT × 3샘플 = 360건 (k=2, JEV 캐시 재사용)
- 단일 워커 + 타임아웃 40초 (2워커+120초에서 9router hang 확인 → 안정화)
- 페어드: 같은 (질문, 샘플)에서 fF/fT 판정 비교 (McNemar 검정)

## 결과 (180쌍)

| cls | fF no | fT no | 차이 |
|---|---|---|---|
| yes (정답) | 5.9% (3/51) | 9.8% (5/51) | -3.9pp |
| block (무답) | 0.9% (1/114) | 4.4% (5/114) | -3.5pp |
| valid | 0.0% (0/15) | 13.3% (2/15) | -13.3pp |
| **전체** | **2.2% (4/180)** | **6.7% (12/180)** | **-4.4pp** |

- **McNemar: fF worse 0 / fF better 8, N=8, p=0.0078** — 통계적으로 유의 (p<0.01)
- 8개 불일치 케이스 **전부 fF 우세** (반대 사례 0건)

## 결론
1. **fF(무프레이밍)가 메모리 인용 유지에 유리** — 페어드 불일치 전부 fF 우세 (p=0.0078)
2. fT(프레이밍 헤더)는 오히려 메모리 활용을 해침 — "[직접적 답이 없다면 무시하라]" 지시가 모델이 메모리를 건너뛰게 만드는 것으로 해석
3. **운영 반영: 프레이밍 도입하지 않음 (현행 fF 유지)** — k=2 + fF 조합이 메모리 인용 97.8% 유지
4. k=2 노출 전략 (stage87 채택) + fF 조합이 유효 — 추가 변경 불필요
