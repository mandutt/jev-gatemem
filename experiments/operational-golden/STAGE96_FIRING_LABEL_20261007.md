# STAGE96 — abstain_p 발동 쿼리 라벨링 + production-exact 재현 (2026-10-07)

## 요약

**b-ai F#1 "7+7건 라벨링" 수행 — 발동 쿼리는 "정직 거부"가 아니라 사실 질문 과다거부 3건 포함. a-ai/b-ai의 "단기 접속사 = True Negative" 해석 기각. τ 조정으로는 해결 불가 (모델 판정 품질 문제).**

## 배경

- b-ai v6 답변 F#1: "발동 7건과 비발동 7건을 무작위로 뽑아 '그 쿼리에 필요한 정보가 코퍼스에 있었는가'를 라벨링(14건). 발동 7건이 전부 저정보/무답이면 정직한 거부, 정답이 있던 쿼리가 섞여 있으면 τ 상향 검토"
- a-ai: 발동 쿼리("아까"/"일단"/"지금"/"cron에")는 "단기 세션 접속사" → 건강한 True Negative 주장

**재현 해석**:
1. **발동은 쿼리·코퍼스 의존 확정** (b-ai "재현되면 쿼리·코퍼스 의존") — 변동성 아님
2. **replay에서 abstain_p가 대부분 더 높음** (0.31→0.80, 0.37→0.78, 0.42→0.70) — trace에서 안 걸린 쿼리도 재현 시 gate 발동. **운영 중 더 많은 빈 컨텍스트 발생 가능 = 과다거부 확대 위험**
3. **작업 지시에서도 ap 0.80** ("그래 보강해줘") — JEV가 명령형 쿼리를 무답으로 오판. "정직 거부"가 아니라 **명령형 오판**
4. 9번(0.38→0.27)은 경계 값 변동 — 모델 비결정성

## 판정

1. **a-ai "단기 접속사 True Negative" 기각** — 발동 쿼리는 접속사가 아니라 전체 문장이 있었고, 그중 3건은 정답 존재 사실 질문
2. **τ 상향(0.4~0.5)은 trade-off를 바꾸지 못함** — 과다거부 3건의 ap(0.81/0.42/0.37)는 상향 후에도 차단됨. 작업 지시 6건(0.31~0.49)만 통과 → 오주입 노출 증가. 즉 τ는 과다거부를 구제하지 못하고 오주입만 늘림
3. **근본 원인은 모델 판정 품질** — 사실 질문에 abstain_p 0.81을 주는 JEV의 closed-set choice 특성. abstain_p를 신뢰해서 gate로 쓰는 구조 자체가 위험 (정답까지 빈 컨텍스트)
4. **canary L2_YES(정답 abstain>0 즉시 알림)가 이 과다거부를 첫날부터 잡도록 보장** — 라벨링 결과를 기준선으로, "아까 rows..."류 재발 시 알림
