# STAGE107/108 — k=3 정답 활용률 실측 (2026-10-10)

## 배경
- 사안 A(노출 k=2)는 stage93/94 소비 QA에서 **정답 활용 −16pp** (65.9% vs k=5 86.4%)로 보류됨
- k=3은 이전에 소비 QA로 실측된 적 없음 → 절충 후보로 실측 필요 (사용자 승인)

## 설계
- **생성**: deepcombo (Hermes 메인 모델, 9router) — stage93/94와 동일 소비 환경
- **판정**: tokenharbor/claude-haiku-5.5:free — "응답이 메모리 속 정답을 활용했는가" (yes/no)
- **대상**: live60 (yes 17 + valid 5 = 정답군 22, block 38), JEV choice 결과 재사용 (stage93_jev_rows.json)
- **k=3, framing OFF** — k=2/k=5 비교 셀은 stage93 기존 결과 사용

- 같은 질문·같은 조건인데 deepcombo 재생성만으로 판정이 뒤집힘

### k 비교 정리 (정답 활용)
| 조건 | 값 | 성격 |
|---|---|---|
| k=2 (stage93/94, 1회) | 65.9% | 1회 측정 |
| **k=3 (본 실험, 3-run)** | **71.2% (50~86%)** | 편차 큼 |
| k=5 (stage93/94, 1회) | 86.4% | 1회 측정 |

## 해석
1. **k=3 정답 활용은 3-run 평균 71.2% — k=2보다 좋고 k=5보다 낮은 중간 수준**
2. **그러나 run 간 ±18pp 요동 (50~86%)** — deepcombo 생성 비결정성(temperature 0.2)이 지배적
3. **→ k=2 vs k=5의 16pp 차이(65.9↔86.4)도 1회 측정이었으므로 노이즈 범위일 수 있음** — 기존 결론의 신뢰성에 의문
4. **측정 방법론 자체의 한계 노출**: 소비 QA 정답 활용률은 1회 측정으로 단정 불가

## 결론
- **k=3 채택 보류** — 안정성 미확보 (3-run flip 59%)
- **판정 방법론 개선 필요 후 재실측**:
  1. 다수결 (3회 생성 → 2/3 일치 판정) — 콜 3배

  3. 기준은 유지하되 온도를 낮추거나 0 고정 가능성 검토 (사용자: 온도 고정은 모델 본연 방해 — 기각됨)
