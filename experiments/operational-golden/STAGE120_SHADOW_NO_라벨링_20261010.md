## 1. 판정 기준 (사용자와 합의)

- **work**: 명령/지시/진행 확인 ("~해줘", "계속", "확인") — 메모리 불필요
- **need**: 과거 사실/설정/결과를 물어보는 질문 — 메모리 검색 필요했음
- **noopen**: 시스템 메시지·문서 첨부·분류 불가

## 3. 자동 분류(키워드)와의 일치: 60% (30/50)

| 자동분류 → 사용자 | 건수 | 예시 |
|---|---|---|
| 질문 → work | 9 | "텔레그램 다시 보여줄래?", "확인해줄래?", "진행할 수 있어?", "들어갔어?" |
| 작업지시 → need | 1 | "source_timestamp는 backfilled_at이 있을 때만 의미있는 속성이 되겠네" (판단 질문) |

**불일치 핵심**: 자동 분류는 의문형 어미(~까? ~래? ~볼래?)를 질문으로 오인 — 실제로는 작업 지시/진행 확인이 다수.

## 4. 결론

1. **NO의 64%는 작업지시** — a-ai의 해석("NO = 작업지시 거부, 정상 동작")을 사용자 라벨로 **확정**
2. **28%는 need** — gate NO가 실제 검색 필요 턴을 놓침 (과다거부). 단, 이 비율은 실험 밀집 기간 측정치로,
   작업지시가 적은 일반 구간에서는 need 비율이 더 높을 수 있음
3. **작업지시 비율 ≈ 2/3** → shadow NO 경고 임계값을 **0.30 → 0.75**로 상향
   (a-ai 권고 0.60보다 보수적. 50% 초과는 "참고" 안내로 완충)
4. 실제 과다거부 감시는 **NO율이 아니라 canary L2_YES(정답 abstain)**가 1차 센서
